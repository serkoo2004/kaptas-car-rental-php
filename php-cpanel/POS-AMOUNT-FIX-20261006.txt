Fix:
PurchAmount integer callbacks use minor units (kurus). The old code multiplied
them by 100 again. The callback parser now treats an integer as minor units
and an explicit two-decimal value as major units. For example, 1253621 and
12536.21 both represent 12536.21 TRY. No guessing based on expected amount.
All other quote/enrollment/Search amount conversions retain their semantics.
